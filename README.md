# 红魔战术室

一个运行在 Windows 本机的 FC Online 阵容与战术助手。默认阵容为曼联队套 4-1-2-3，适用于手动排位分析。项目仅使用 Python 标准库，不需要安装额外依赖。

跨设备维护时，请让 Verdent 或其他编码代理先阅读 [维护约定](AGENTS.md) 和 [项目需求与维护基线](PROJECT_REQUIREMENTS.md)。这些文档随 Git 同步，不依赖聊天记录；不支持自动读取 `AGENTS.md` 的工具需要在任务中明确引用。项目架构、数据流程和接口说明见[完整技术文档](TECHNICAL_DOCUMENTATION.md)。

## 启动

需要 Python 3.10 或更高版本。打开 Windows 命令提示符：

```bat
cd /d D:\projects\fc-online-agent
python server.py
```

在浏览器访问 `http://127.0.0.1:8765`。服务仅监听本机，按 `Ctrl+C` 停止；如端口被占用，启动前设置 `set FC_PORT=8766` 并访问对应端口。

## 配置模型

在“战术助手”的“模型来源”中可随时选择“OpenAI”“DeepSeek”“其他在线服务”或“本地 Ollama”（按页面顺序），对话和截图识别共用当前选择，无需为切换重启网站。页面会在当前浏览器记住上次选择的模型来源，刷新或重新打开时恢复；无记录时默认 OpenAI。浏览器存储被清除、禁用或切换浏览器、端口时可能恢复默认选择，模型选择不随 Git 同步。使用 OpenAI 前需配置密钥，对话和阵容摘要会发送给 OpenAI，主动发送的截图也会传给 OpenAI，调用可能收费；切换时清空发送给模型的对话上下文，页面上之前的消息仍可见。OpenAI 和 DeepSeek 密钥可在页面“设置”中更新并立即生效；环境变量和模型名称变更仍需重启网站。

如需使用本地模型，请在页面选择“本地 Ollama”。该模式默认连接本机 Ollama（`http://127.0.0.1:11434/v1`），文字和截图识别均使用 `qwen2.5vl:3b`，无需 API Key：

1. 从 [Ollama 官网](https://ollama.com/download/windows)下载安装并启动 Ollama（该模型需要 Ollama 0.7.0 或更新版本）。
2. 打开新的 Windows 命令提示符，下载模型：

```bat
ollama pull qwen2.5vl:3b
```

模型下载约 3.2 GB，首次加载可能需要数分钟，并需要足够的磁盘空间和内存。等待下载完成后，启动 Ollama 并按上面的“启动”步骤启动网站。首次加载或纯 CPU 运行可能较慢；截图识别的结果请逐项核对。页面的“已配置 · 未验证”只说明配置存在，不代表模型已下载或服务已连接。

如需换用已下载的其他模型，在启动网站的同一个命令提示符中设置名称，例如：

```bat
set FC_OLLAMA_CHAT_MODEL=qwen2.5vl:7b
set FC_OLLAMA_VISION_MODEL=qwen2.5vl:7b
python server.py
```

截图识别必须使用支持图片输入的模型。`qwen2.5vl:7b` 下载约 6 GB，需要先运行 `ollama pull qwen2.5vl:7b`；按自己的硬件选择模型。模型配置只在当前命令窗口生效，修改后需重启网站。该本地模式的默认模型在本机推理，但如自行选择 Ollama 云模型或配置远程服务，数据可能发送到对应服务商。

### OpenAI 和 DeepSeek

启动后打开页面右上角“设置”，分别保存、更新或删除 OpenAI 和 DeepSeek 密钥，修改后立即用于下一次请求。密钥不会在页面回显，而是使用当前 Windows 用户的 DPAPI 加密后存入本机数据库。它不会随 Git 同步；其他设备或 Windows 用户需要重新设置。DPAPI 主要保护单独复制的数据库文件，无法防止同一 Windows 账户或运行中的程序被攻破。

也可在启动网站的同一个 Windows 命令提示符窗口中设置环境变量（可选）：

```bat
set FC_OPENAI_API_KEY=你的OpenAI密钥
set FC_DEEPSEEK_API_KEY=你的DeepSeek密钥
python server.py
```

不需要两个都配置；如需在二者之间切换，请分别配置。页面本机密钥优先于环境变量；删除本机密钥后，若环境变量仍已设置，它会继续生效，页面会显示该状态。密钥不要发到聊天里或写入项目文件。OpenAI 默认使用 `gpt-4.1-mini`，DeepSeek 默认使用 `deepseek-flash`，文字和截图分别可通过 `FC_OPENAI_CHAT_MODEL`、`FC_OPENAI_VISION_MODEL`、`FC_DEEPSEEK_CHAT_MODEL`、`FC_DEEPSEEK_VISION_MODEL` 覆盖。截图必须选用服务商支持图片输入的模型；状态“已配置 · 未验证”仅表示密钥和模型名称已设置，不代表连接、余额或模型能力验证成功。调用在线 API 可能收费，以服务商价格和账户额度为准。[OpenAI 模型说明](https://developers.openai.com/api/docs/models/gpt-4.1-mini)和 [DeepSeek 识图说明](https://api-docs.deepseek.com/guides/vision)可查模型能力。

遇到 OpenAI HTTP 429 时，可能是请求速率超限或 API 额度不足：请稍等再试，并检查 [API 账单](https://platform.openai.com/settings/organization/billing/overview)、项目使用限额及速率限制。ChatGPT 订阅不等于 API 额度；若提示额度不足，等待通常不能解决，需要检查 API 计费和限额。应用不会显示服务商返回的原始错误内容，也不会自动重试。

如果模型返回空内容，页面会在服务提供可识别原因时提示输出长度限制、内容过滤或不支持的工具调用；也可能是模型没有提供最终答复或接口不兼容。请检查当前选择的模型来源，尝试缩短问题或更换兼容模型。不要将原始响应、密钥或私人截图发给他人排查。

### 其他兼容服务

仍可使用兼容 OpenAI Chat Completions 的在线服务：

```bat
set FC_API_BASE=https://你的服务商地址/v1
set FC_API_KEY=你的密钥
set FC_CHAT_MODEL=你的文字模型名称
set FC_VISION_MODEL=你的视觉模型名称
python server.py
```

`FC_API_BASE` 是在线接口根地址，不包含 `/chat/completions`。在线服务必须使用远程 HTTPS 地址和 API Key；不要将密钥写进项目文件、截图或聊天内容。密钥仅由本地服务读取，不发送到网页，也不写入数据库。`FC_CHAT_MODEL` 用于在线对话；`FC_VISION_MODEL` 仅在服务商和具体模型支持图片输入时填写，无法识图的模型不能用于截图识别。若只需在线文字对话，可不设置 `FC_VISION_MODEL`。配置好后在页面选择“其他在线服务”；本地 Ollama 可使用上述独立的 `FC_OLLAMA_CHAT_MODEL` 和 `FC_OLLAMA_VISION_MODEL`。未启动模型服务时仍可编辑阵容及导入球员，但不能使用对话和截图识别。

## 使用

1. 点击球场上的位置，或点击下方 7 个替补席位，手动填写并保存位置、球员、赛季和强化等级，或从本地球员库关联球员。替补席显示关联球员的头像、默认位置、工资、赛季图标、强化等级和总评；赛季无法匹配或图标加载失败时显示文字。默认位置来自 FIFA Addict，不会自动覆盖手动选择的位置。填写有效强化等级时，替补“总评”按缓存总评（假设为 1 强、1 级）加假定满级 +4 和强化估算，不包含队套、军团或细项加成，也不保证与游戏一致；未填写有效强化时显示来源总评，未关联或缺少数据时显示未知。点击替补卡片查看计算说明并编辑，头像及赛季信息遵循相同的数据来源和回退规则。替补不设置个人战术，也不会自动与首发交换；已保存替补会进入战术助手摘要和同步快照。首发位置可按场上位置从下拉列表选择个人战术；个人战术按位置保存，换人或清空球员后仍保留。选项参考游戏资料，LM/RM 参考旧资料，可能随版本变化，请以游戏内为准；未设置不是游戏默认值。切换场上位置前会提示确认清除当前个人战术选择，进攻和防守倾向保留。旧版保存的不匹配选项会标注并保留，直到用户替换或清除。点击首发阵容旁的“球队战术”打开弹窗，手动填写并保存球队设置；未填写项显示为未设置，关闭未保存的弹窗时会提示确认。战术不会从截图自动识别或推断，输入限制是本工具的校验边界，不代表游戏官方规则。截图可用微信或 Windows 截图工具复制后，在应用页面按 `Ctrl+V` 粘贴（也可先打开“导入截图”窗口）；如正在文字输入框中粘贴文字，请先点击页面空白处再粘贴图片。也可点击“导入截图”选择本地图片，或点击“截取桌面或游戏窗口”并在浏览器弹窗中选择要截取的屏幕或窗口；截图后立即停止共享。粘贴或桌面截图可在预览图上拖动选取识别区域，或使用完整截图；本地文件按原图发送。粘贴图片支持 PNG、JPEG、WebP，最大 20 MB、4000 万像素；发送前按需压缩，发送数据最大 4 MB。本地文件最大 4 MB。确认画面不含敏感信息后，点击“发送截图并识别”，由视觉模型识别，再逐项检查、修改并选择位置确认写入。只有点击发送才会将截图发送给配置的视觉模型服务（无选择记录时默认是 OpenAI）。桌面截图需使用支持屏幕共享的 Chrome 或 Edge 等浏览器；如果游戏全屏画面无法捕获，请尝试游戏窗口或无边框模式。
首发球场参考游戏战术板展示头像、总评、工资、赛季图标和填写的强化等级。强化等级支持数字、`+5` 或 `5强` 等写法，1–4、5–7、8–10、11–13 分别以铜、银、金、钻石样式展示；其他内容保留并以中性色显示。窄屏可左右滑动战术板。请先从本地球员库关联对应卡片；基准总评和工资来自缓存，缺失显示“—”，头像加载失败或未关联时显示姓名首字，赛季图标不可用时显示赛季文字。球场显示估算总评：假设 FIFA Addict 缓存总评为 1 强、1 级基准，并假设球员已满级（5 级，全能力 +4）；满级加成参考社区及韩服资料，尚未找到国服官方原文确认，可能与游戏不同。按已保存首发的强化等级累加强化提升，假设全部已填首发属于曼联，并按首发人数计算曼联套及银卡、金卡、钻石军团；同一球员只取适用军团中的最高加成，不叠加。未包含对抗、头球等细项加成、其他组合或替补人数，游戏内可能不同。强化等级、关联球员或影响军团人数的其他首发等级缺失时，无法确定的总评显示“—”；点击球员位置、悬停或使用辅助技术可查看计算依据及来源时间。头像及赛季图标由浏览器联网获取，图片服务器可见访问者 IP。

2. 在“球员资料”的在线搜索中输入非空的球员名称；过短的英文搜索词可能只筛选数据源的默认结果，结果不完整，搜索词会发送至 FIFA Addict；从结果中选择赛季并导入详情；每次在线搜索结束后结果列表会回到顶部。球员列表最左侧显示位置：前场红色、中场绿色、后场蓝色、门将金色，未知位置显示灰色；列表右侧显示左右脚数值（绿色标记惯用脚）、圆圈工资及总评；点击球员名称打开详情，查看在线球员或缺少完整详情的旧缓存时会联网获取，但不会自动导入或修改缓存。旧缓存要保存完整详情，可手动点击“刷新”；获取不到时保留旧缓存。也可以前往网站复制详情页链接，粘贴到页面导入。点击球场位置，再从本地球员库关联到该位置。本地球员库的搜索只覆盖已经导入的球员；在线搜索结果可能不完整，依赖第三方网站可用性。搜索结果和本地球员库中的头像、赛季、左右脚及特殊能力图标由浏览器从 FIFA Addict 图片服务器加载，服务器可见访问者 IP；图片未保存到本机。头像离线或加载失败时显示姓名首字，未匹配的赛季或图标加载失败时保留赛季文字。赛季图标依照当前网站映射，网站更新后可能需要调整。刷新失败时保留缓存并提示；时间显示的是本工具获取数据的时间，不是网站更新时间。
3. 在战术助手中提问。对话会发送给配置的模型服务（无选择记录时默认是 OpenAI），包含已保存阵容、个人及球队战术和已关联球员的数据摘要；未保存的编辑不会发送，也不会自动发送截图。推荐说明打法、BP 预算和遇到的问题。对话保留在当前网页会话中，不保存在本地数据库。

阵容和球员缓存位于项目 `data/` 文件夹，可自行备份。不要在服务运行时手动编辑数据库。截图不会由本工具写入磁盘。

## 多设备手动同步

同步文件 `sync/snapshot.json` 包含阵容（含个人和球队战术）及已缓存的球员资料，不包含本机密钥、模型设置、截图或聊天记录。新版导出版本 3，旧版程序无法读取，须先更新其他设备；新版可导入版本 1、2 快照。导入版本 1 会将战术设为未设置，若本机已保存战术则需额外确认；版本 1 和 2 不含替补，导入时会清空本机替补，若本机有替补数据则需另外确认。版本升级可能使旧基线显示本机数据变化，不会自动重置基线。每台 Windows 设备都需要独立设置密钥；不要将 `data/`、数据库或 `.env` 文件提交到 Git。

1. 在当前设备先拉取远程更新。如果 `sync/snapshot.json` 有更新，启动网站，在“设置”中选择“导入同步数据”，确认覆盖本机阵容和球员缓存。导入前请先保存页面中的编辑，并确认不再需要被覆盖的本机数据。
2. 正常编辑并保存阵容或导入球员后，在“设置”中选择“导出同步数据”。如果文件包含尚未导入的变更，先检查并导入；只有确认要舍弃文件中的变更时才选择覆盖。
3. 在提交前检查 `sync/snapshot.json` 的差异，确认阵容备注等内容适合共享，再自行执行 Git 提交和推送。应用不会自动执行 Git 操作。
4. 在另一台设备拉取更新，启动网站并在“设置”中导入，再进行编辑和导出。若两台设备都各自修改过，请先保留备份并手动合并；不要直接覆盖另一台设备的数据。

Git 合并冲突必须先在编辑器中处理，移除冲突标记并确认 JSON 和阵容关联有效后再导入。导入失败不会部分覆盖本机数据。同步文件及其 Git 历史对仓库成员可见，即使后来删除内容，历史中仍可能保留；公开仓库会向所有人公开这些内容。

## 数据边界

FIFA Addict 是独立第三方球迷站，并非游戏官方数据库。其中文页面不保证是国服实时数据，也不保证对应卡片已在国服上架。导入时通过详情页及其会话接口获取数据源返回的全部基础能力、特殊能力及效果、体型、基本资料和俱乐部经历；数据源未提供的内容显示未知或暂无记录。特殊能力图标按数据源 ID 由浏览器加载，不保存图片；同步快照保存 ID 和效果。基础能力不包含用户填写的强化等级或队套加成，详情页摘要可能采用不同等级，游戏内实际显示也可能不同。当前不提供国服价格或自动判断曼联队套资格，请以游戏内信息为准。网站结构或可用性变化可能导致导入失败。
